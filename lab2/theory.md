# Лабораторная работа 2 — Управление процессами в Linux

## Теоретическая база

### Файловая система /proc

`/proc` — виртуальная (псевдо) файловая система ядра Linux. Не хранит данные на диске; содержимое генерируется ядром «на лету» при каждом обращении. Для каждого живого процесса с PID=N существует каталог `/proc/N/`.

| Файл | Содержимое |
|------|-----------|
| `/proc/N/status` | Текстовые поля: Name, Pid, Tgid, PPid, VmRSS, Threads и др. |
| `/proc/N/statm` | 7 чисел в страницах: size, resident, shared, text, lib, data, dt |
| `/proc/N/sched` | Планировщик CFS: `se.sum_exec_runtime`, `nr_switches` и др. |
| `/proc/N/stack` | Трассировка стека ядра (требует root) |
| `/proc/N/wchan` | Имя системного вызова, в котором заблокирован процесс |
| `/proc/N/fd/` | Символические ссылки на открытые файловые дескрипторы |

## Задание 1 — Вывод PID процессов по состоянию

**Файл:** `task1.sh`

```bash
ps -eo pid,stat --no-headers | awk '$2 ~ /^[RSDZT]/ {print $1}'
```

### Команда `ps`

`ps` — вывод снимка текущих процессов.

| Флаг/опция | Описание |
|------------|---------|
| `-e` | Показать все процессы (эквивалент `-A`) |
| `-o pid,stat` | Выводить только колонки PID и STAT |
| `--no-headers` | Не печатать заголовок таблицы |

### Состояния процессов (поле STAT)

| Код | Состояние |
|-----|----------|
| `R` | Running — выполняется или готов к выполнению |
| `S` | Sleeping (прерываемый сон) — ожидает события |
| `D` | Disk sleep (непрерываемый сон) — ожидает I/O |
| `Z` | Zombie — завершился, но родитель не вызвал `wait()` |
| `T` | Stopped — остановлен сигналом SIGSTOP/SIGTSTP |

### Команда `awk`

`awk` — построчная обработка текста с паттернами и действиями.

| Элемент | Описание |
|---------|---------|
| `$2 ~ /regex/` | Второе поле ($2) соответствует регулярному выражению |
| `^[RSDZT]` | Строка начинается с одного из перечисленных символов |
| `{print $1}` | Вывести первое поле ($1 = PID) |

## Задание 4 — Исследование /proc для конкретного процесса

**Файл:** `task4.sh`

### Создание фонового процесса

```bash
sleep 10000 &
PID=$!
```

| Элемент | Описание |
|---------|---------|
| `sleep N` | Пауза на N секунд (используется как безопасный «висящий» процесс) |
| `&` | Запуск в фоне |
| `$!` | Специальная переменная — PID последнего фонового процесса |

### Чтение /proc

```bash
tail -5 /proc/$PID/stack          # последние 5 кадров стека ядра
grep -E "^(Name|PPid|Kthread|Threads):" /proc/$PID/status
grep -E "^(Tgid|Pid):" /proc/$PID/status
```

### Tgid vs Pid

- **Pid** — идентификатор конкретного потока.
- **Tgid** (Thread Group ID) — PID лидера группы потоков, совпадает с «PID процесса» в смысле пользователя.
- У однопоточного процесса `Tgid == Pid`. В многопоточном — все потоки имеют одинаковый `Tgid`, но разные `Pid`.

### Завершение процесса

```bash
kill "$PID"
```

По умолчанию посылает `SIGTERM` (15) — вежливый запрос завершения.

## Задание 5 — Завершение «молодых» процессов

**Файл:** `task5.sh`

```bash
ps -eo pid,etimes --no-headers | while read -r pid elapsed; do
    [ "$pid" -le 1 ] && continue
    [ "$pid" -eq "$$" ] && continue
    if [ "$elapsed" -lt "$N" ] 2>/dev/null; then
        kill -0 "$pid" 2>/dev/null && kill "$pid" 2>/dev/null && echo "$pid" >> killed.log
    fi
done
```

| Элемент | Описание |
|---------|---------|
| `$$` | PID текущего shell-скрипта |
| `[ "$pid" -le 1 ]` | Пропуск PID 0 (swapper) и 1 (init/systemd) |
| `kill -0 $pid` | Проверка существования процесса без отправки сигнала (сигнал 0) |
| `kill $pid` | Отправка SIGTERM |
| `>> killed.log` | Дозапись в лог-файл |
| `continue` | Переход к следующей итерации цикла |

## Задание 7.2 — Трассировка системных вызовов через strace

**Файл:** `task7_2.sh`


### Команда `strace`

`strace` перехватывает и записывает все системные вызовы процесса.

| Флаг | Описание |
|------|---------|
| `-e trace=network` | Фильтр: только сетевые syscalls (`socket`, `connect`, `send`, `recv` и др.) |
| `-e trace=file` | Фильтр: только файловые syscalls (`open`, `read`, `write`, `stat` и др.) |
| `-o <файл>` | Перенаправить вывод в файл вместо stderr |

## Задание 9 — Среднее время выполнения из /proc/sched

**Файл:** `task9.sh`

```bash
sum_exec=$(awk '/^se\.sum_exec_runtime/ {print $NF; exit}' "$sched_file")
nr_switches=$(awk '/^nr_switches/ {print $NF; exit}' "$sched_file")
art=$(awk "BEGIN {printf \"%.6f\", $sum_exec / $nr_switches}")
```

### Поля /proc/N/sched

| Поле | Описание |
|------|---------|
| `se.sum_exec_runtime` | Суммарное время на CPU (мс) с момента создания процесса |
| `nr_switches` | Количество переключений контекста (раз выходил с CPU) |

### Вычисление Average Running Time (ART)

```
ART = se.sum_exec_runtime / nr_switches
```

ART — средняя продолжительность одного кванта процессора.

### sort с разделителем

```bash
sort -t= -k3 -n
```

| Флаг | Описание |
|------|---------|
| `-t=` | Разделитель полей — символ `=` |
| `-k3` | Сортировать по 3-му полю |
| `-n` | Числовая сортировка |

## Задание 11 — Процесс с наибольшим RSS через /proc

**Файл:** `task11.sh`

```bash
for statm_file in /proc/[0-9]*/statm; do
    read -r _size resident _ < "$statm_file" 2>/dev/null || continue
    if [ "$resident" -gt "$max_resident" ]; then ...
done

page_kb=4
mem_kb=$((max_resident * page_kb))
```

### /proc/N/statm

Файл содержит 7 чисел в единицах **страниц памяти** (обычно 4 КБ):

```
size resident shared text lib data dt
```

| Поле | Описание |
|------|---------|
| `size` | Общий виртуальный размер |
| `resident` | Страниц в RAM (RSS) |

### Глобинг

`/proc/[0-9]*/statm` — shell разворачивает это в список файлов, где `[0-9]*` соответствует каталогам с числовыми именами (PID).

### top в пакетном режиме

```bash

```

| Флаг | Описание |
|------|---------|
| `-b` | Batch mode — вывод в stdout без интерактивного UI |
| `-n 1` | Одна итерация обновления |
| `-o RES` | Сортировать по колонке RES (резидентная память) |

## Задание 12 — Изменение приоритета долгих процессов

**Файл:** `task12.sh`

```bash
ps -eo pid,etimes --no-headers | while read -r pid elapsed; do
    if [ "$elapsed" -gt "$N" ]; then
        renice "$NICE_VAL" -p "$pid"
    fi
done
```

### Приоритет и nice

- **nice** — значение от -20 (высший приоритет) до 19 (низший).
- По умолчанию новый процесс получает nice = 0.
- Только root может понижать nice (повышать приоритет).

### Команда `renice`

```bash
renice ЗНАЧЕНИЕ -p PID
```

| Флаг | Описание |
|------|---------|
| `-p` | Указать PID |
| `-g` | Указать PGID (группу процессов) |
| `-u` | Указать пользователя |

### Проверка результата

```bash
ps -eo pid,ni,etimes,comm --no-headers | sort -k3 -nr | head -20
```

Поле `ni` в `ps` — текущее значение nice.
