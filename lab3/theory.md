# Лабораторная работа 3 — Планирование задач и межпроцессное взаимодействие

## Теоретическая база

### Планировщики задач в Linux

Linux предоставляет несколько механизмов отложенного и периодического запуска команд:

| Инструмент | Тип | Описание |
|-----------|-----|---------|
| `at` | Одноразовый | Выполнить команду в указанное время |
| `cron` | Периодический | Выполнять по расписанию (crontab) |
| `systemd.timer` | Периодический | Современная альтернатива cron |

### Сигналы в Linux

Сигнал — асинхронное уведомление процессу о событии.

| Сигнал | Номер | Действие по умолчанию | Описание |
|--------|-------|----------------------|---------|
| `SIGTERM` | 15 | Завершить | Вежливый запрос на остановку |
| `SIGKILL` | 9 | Завершить | Принудительное завершение (нельзя перехватить) |
| `SIGSTOP` | 19 | Остановить | Приостановить выполнение (нельзя перехватить) |
| `SIGCONT` | 18 | Продолжить | Возобновить остановленный процесс |
| `SIGUSR1` | 10 | Завершить | Пользовательский сигнал №1 |
| `SIGUSR2` | 12 | Завершить | Пользовательский сигнал №2 |

### Именованные каналы (FIFO / Named Pipe)

FIFO — файл специального типа (`p`), обеспечивающий однонаправленный поток данных между процессами. Существует в файловой системе (в отличие от анонимных каналов `|`).

```
Процесс A (writer) --> [FIFO файл] --> Процесс B (reader)
```

## Задание 1 — Базовые операции с файлами и сетью

**Файл:** `task1.sh`

```bash
mkdir ~/test && echo "catalog test was created successfully" >> ~/report && \
    touch ~/test/$(date +"%Y-%m-%d_%H-%M-%S")
ping -c 1 www.net_nikogo.ru > /dev/null 2>&1 || \
    echo "$(date +"%Y-%m-%d %H:%M:%S") host www.net_nikogo.ru is unreachable" >> ~/report
```

### Команды и операторы

| Элемент | Описание |
|---------|---------|
| `mkdir` | Создать каталог |
| `&&` | Выполнить следующую команду только если предыдущая успешна (exit 0) |
| `\|\|` | Выполнить следующую команду только если предыдущая провалилась (exit ≠ 0) |
| `>>` | Дозапись в файл (не перезаписывает) |
| `touch` | Создать файл или обновить время доступа |
| `date +"%Y-%m-%d_%H-%M-%S"` | Форматированная текущая дата/время |
| `ping -c 1` | Отправить один ICMP-пакет |
| `> /dev/null` | Перенаправить stdout в «чёрную дыру» (подавить вывод) |
| `2>&1` | Перенаправить stderr в stdout (оба потока уходят в /dev/null) |
| `$()` | Подстановка результата команды (command substitution) |

## Задание 2 — Отложенный запуск через `at`

**Файл:** `task2.sh`

```bash
at now + 2 minutes -f "$(realpath "$(dirname "$0")/task1.sh")"
tail -f ~/report
```

### Команда `at`

`at` — запланировать однократное выполнение команды или скрипта.

| Элемент | Описание |
|---------|---------|
| `at now + 2 minutes` | Запустить через 2 минуты от текущего момента |
| `-f <файл>` | Выполнить команды из указанного файла |
| `atq` | Просмотр очереди задач |
| `atrm <ID>` | Удалить задачу из очереди |

Демон `atd` должен быть запущен для работы `at`.

### Вспомогательные команды

| Команда | Описание |
|---------|---------|
| `realpath <путь>` | Вернуть абсолютный путь (раскрывает `..`, `~`, симлинки) |
| `dirname "$0"` | Каталог, в котором находится текущий скрипт |
| `tail -f <файл>` | Следить за файлом в реальном времени (выводит новые строки по мере добавления) |

## Задание 3 — Периодический запуск через `cron`

**Файл:** `task3.sh`

```bash
SCRIPT="$(realpath "$(dirname "$0")/task1.sh")"
DOW=$(date +%w)
(crontab -l 2>/dev/null; echo "5 * * * $DOW bash $SCRIPT") | crontab -
crontab -l
```

### Формат crontab

```
минута  час  день_месяца  месяц  день_недели  команда
  5      *       *           *       $DOW       bash $SCRIPT
```

| Поле | Диапазон | Описание |
|------|---------|---------|
| минута | 0–59 | `5` = в 5-ю минуту каждого часа |
| час | 0–23 | `*` = каждый час |
| день месяца | 1–31 | `*` = каждый день |
| месяц | 1–12 | `*` = каждый месяц |
| день недели | 0–7 (0,7=вс) | `$DOW` = только текущий день недели |

### Управление crontab

| Команда | Описание |
|---------|---------|
| `crontab -l` | Вывести текущие задачи |
| `crontab -e` | Редактировать таблицу |
| `crontab -r` | Удалить всю таблицу |
| `crontab -` | Читать таблицу из stdin |

### Обновление crontab без потери существующих записей

```bash
(crontab -l 2>/dev/null; echo "новая строка") | crontab -
```

`crontab -l 2>/dev/null` — вывести существующие записи; `2>/dev/null` скрывает ошибку если таблицы нет. Результат объединяется с новой строкой и подаётся на stdin `crontab -`.

### date +%w

Возвращает номер дня недели: 0 = воскресенье, 1 = понедельник, ..., 6 = суббота.

## Задание 4 — Управление CPU через SIGSTOP/SIGCONT

**Файлы:** `task4.sh`, `task4_worker.sh`

### task4_worker.sh

```bash
while true; do
    echo $((99999 * 88888)) > /dev/null
done
```

Бесконечный цикл, создающий нагрузку на CPU. Результат арифметики отбрасывается в `/dev/null`.

### task4.sh — троттлинг процесса

```bash
bash "$WORKER" &
PID1=$!

while kill -0 "$PID1" 2>/dev/null; do
    kill -CONT "$PID1" 2>/dev/null
    sleep 0.1
    kill -STOP "$PID1" 2>/dev/null
    sleep 0.9
done
```

**Принцип работы:** процесс активен 0.1 с из каждой секунды → ~10% CPU.

| Сигнал | Эффект |
|--------|--------|
| `SIGSTOP` (19) | Немедленно приостанавливает процесс (нельзя перехватить или игнорировать) |
| `SIGCONT` (18) | Возобновляет выполнение остановленного процесса |
| `SIGTERM` (15) | Запрашивает завершение |

```bash
kill -0 "$PID"    # Проверка существования процесса без отправки сигнала
kill -CONT "$PID" # = kill -18 "$PID"
kill -STOP "$PID" # = kill -19 "$PID"
```

### Запуск нескольких фоновых процессов

```bash
bash "$WORKER" &; PID1=$!
bash "$WORKER" &; PID2=$!
bash "$WORKER" &; PID3=$!
```

`$!` всегда содержит PID **последнего** запущенного фонового процесса, поэтому его нужно сохранять сразу после `&`.

## Задание 5 — Межпроцессное взаимодействие через FIFO

**Файлы:** `task5_generator.sh`, `task5_handler.sh`

### Создание именованного канала

```bash
PIPE=/tmp/task5_pipe
[ -p "$PIPE" ] || mkfifo "$PIPE"
```

| Команда/флаг | Описание |
|-------------|---------|
| `mkfifo <путь>` | Создать именованный канал (FIFO) |
| `[ -p "$PIPE" ]` | Проверить, является ли файл каналом (pipe) |

### task5_generator.sh — запись в FIFO

```bash
while true; do
    read -r LINE
    echo "$LINE" > "$PIPE"
    [ "$LINE" = "QUIT" ] && break
done
```

`echo ... > "$PIPE"` — запись в FIFO блокируется до тех пор, пока читатель не откроет другой конец канала.

### task5_handler.sh — чтение из FIFO

```bash
(tail -f "$PIPE") | while IFS= read -r LINE; do
    case "$LINE" in
        "+")   MODE="add" ;;
        "*")   MODE="multiply" ;;
        "QUIT") exit 0 ;;
        *)
            if [[ "$LINE" =~ ^-?[0-9]+$ ]]; then
                case "$MODE" in
                    "add")      VALUE=$((VALUE + LINE)) ;;
                    "multiply") VALUE=$((VALUE * LINE)) ;;
                esac
            fi
    esac
done
```

| Элемент | Описание |
|---------|---------|
| `tail -f` | Следить за файлом/каналом и выводить новые данные |
| `IFS=` | Пустой разделитель полей — сохраняет пробелы в начале/конце строки |
| `read -r` | Не интерпретировать `\` как escape-символ |
| `case ... esac` | Ветвление по значению переменной (аналог switch) |
| `[[ "$LINE" =~ regex ]]` | Регулярное выражение в условии (bash-расширение) |
| `^-?[0-9]+$` | Паттерн: опциональный минус, одна или более цифр, конец строки |
| `$(( ))` | Арифметические вычисления в bash |

### Сохранение PID генератора

```bash
echo $$ > /tmp/task5_gen.pid
```

`$$` — PID текущего процесса. Сохраняется в файл, чтобы handler мог завершить генератор по команде QUIT.

## Задание 6 — Межпроцессное взаимодействие через сигналы

**Файлы:** `task6_generator.sh`, `task6_handler.sh`

### task6_handler.sh — установка обработчиков сигналов

```bash
trap 'on_usr1' USR1
trap 'on_usr2' USR2
trap 'on_term' TERM
```

### Команда `trap`

`trap` перехватывает сигналы и привязывает к ним shell-функции или команды.

```bash
trap 'команда' СИГНАЛ [СИГНАЛ...]
trap '' СИГНАЛ    # игнорировать сигнал
trap - СИГНАЛ     # восстановить обработчик по умолчанию
```

| Сигнал | Использование в задании |
|--------|------------------------|
| `USR1` | Переключить режим на сложение (`OP="add"`) |
| `USR2` | Переключить режим на умножение (`OP="multiply"`) |
| `TERM` | Завершить работу handler |

### task6_generator.sh — отправка сигналов

```bash
while [ ! -f "$PID_FILE" ]; do sleep 0.2; done
HANDLER_PID=$(cat "$PID_FILE")

case "$LINE" in
    "+")    kill -USR1 "$HANDLER_PID" ;;
    "*")    kill -USR2 "$HANDLER_PID" ;;
    "TERM") kill -TERM "$HANDLER_PID" ;;
esac
```

Генератор ждёт появления файла с PID handler-а, затем транслирует команды пользователя в сигналы.

### Основной цикл handler-а

```bash
while true; do
    case "$OP" in
        "add")      VALUE=$((VALUE + 2)) ;;
        "multiply") VALUE=$((VALUE * 2)) ;;
    esac
    echo "$VALUE"
    sleep 1
done
```

Сигналы прерывают `sleep` и вызывают соответствующий обработчик `trap`, после чего цикл продолжается с новым значением `OP`.
